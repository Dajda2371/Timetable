# Scheduler benchmark results

Reference machine: macOS 26.6.2 on ARM64, 8 logical CPUs, Python 3.14.7,
OR-Tools 9.15.6755. Runs use seed 0, 8 search workers, and a 180-second
search budget. Wall time includes model preparation and output verification.

The synthetic inputs are generated by `benchmark_scheduler.py`: five eight-period
days, ten subjects, 25 weekly lessons per class, per-class lunch candidates
5/6/7, and subject-qualified teachers shared across all classes. A separate
constructed timetable is verified to prove feasibility before each benchmark;
the solver does not receive that timetable as a hint.

These are representative development measurements, not performance guarantees or
proofs of optimality. Parallel search can produce different schedules and quality
scores between runs. The larger model needs substantial memory; worker count can
be reduced through `SolverOptions` or the benchmark's `--workers` argument.
Both recorded cases produced complete, independently verified schedules (2/2);
this small sample is not a statistical feasibility-rate estimate. The 50-class
run eliminated student gaps and same-day repetitions, but did not achieve evenly
balanced days or compact teacher schedules within the budget. Further quality
improvements at this size remain possible; a feasible result does not imply an
optimal timetable.

The example fixture separately passes exact coverage checks for all 204 required
lessons. Before the replacement, 100 seeded runs of the greedy algorithm scheduled
177–203 of those lessons, with no complete result. That original fixture also had
out-of-range lunch candidates, which are now corrected and rejected by validation.
